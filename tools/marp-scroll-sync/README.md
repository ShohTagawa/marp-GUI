# Marp Scroll Sync (marp-GUI) v0.2

Marp デッキ用の、**本文 ↔ スライド 同期プレビュー**拡張。
v0.2 で、プレビュー上での直接編集・スライド単位の操作・完成スライドの再利用（ライブラリ）・原稿の折りたたみが加わった。

原稿（.md）に書き込むものは、標準の marp-cli の出力（PDF / HTML / PNG・発表者ノート）を変えない形式だけにしてある（→「書き戻される記法」）。

## できること

### 同期プレビュー（v0.1 から）
- **ステータスバー**に「いま編集中のカーソル行が Marp の何枚目か」を `Slide 34/78` 形式で常時表示
- サイドの **Webview プレビュー**が、カーソル位置のスライドへ自動スクロール(編集中の箇所が常に見える)
- プレビューの**スライドをクリック**すると、本文の該当行へジャンプ(双方向)
- プレビューの**テキストをクリック**すると、原稿の該当行を**選択＋一時ハイライト**(生`<div>`/`<span>`の本文でも逆引き可)。文字の無い余白クリックはスライド先頭へフォールバック(このときフォーカスはプレビューに残る＝そのまま ↑↓ で送れる)
- **キーでスライド送り**：プレビューでスライドを選んだあと **↑ / ↓** で前後のスライドへ移動(原稿のカーソルとステータスバーも一緒に動く)。**PageUp/PageDown・j/k・Shift+↑↓** は文字選択中でも必ずスライド送り、**Home/End** で先頭/末尾へ
- **文字サイズ/色の微調整**：文字を選択し、プレビュー下部のツールバー `A− [px] A+ 🎨 ✕` または **Cmd+Alt+= / Cmd+Alt+−** で `font-size` を **1px 刻み**で増減、色も変更。テーマ CSS は触らず、その箇所だけ `<span class="ss-tune" …>` を原稿に挿入する。v0.2 からは**プレビュー上でドラッグして選んだ文字**にもそのまま効く（1つの文字のまとまりの中で選んだときだけ）。色見本の「赤(テーマ)」「濃赤」は `var(--accent)` / `var(--accent-dark)` を書くので、配色の違うデックへ持って行っても先の色に従う
- **現在スライドをブラウザでプレゼン**：`Marp: Present`(ツールバーの ▶)で marp-cli(`--html`)が発表用 HTML を生成し、編集中のページから既定ブラウザで開く
- ファイル編集で自動再レンダリング(0.7s デバウンス。プレビューからの編集・サイズ/色の微調整は即時反映)
- **`theme/` 直下の `*.css` を全部自動適用**(`academic` / `tsutawaru-academic`)。`@import "academic"` を解決できるよう `academic.css` を先頭に読む。ローカル画像(`../assets/…`, `./src/…`)も表示

### プレビュー上での直接編集（v0.2）
- プレビューの文字を**ダブルクリック**すると、その段落・箇条書き・見出し・表のセルなどがその場で編集できる。インライン SVG の中の文字は、同じ位置に小さな入力欄が出る
- 確定すると原稿の該当箇所**だけ**が書き換わる（前後の空白や記号はそのまま）
- 箇条書きの追加・削除もプレビューからできる（下の「キー操作」）
- **書き戻したらすぐ保存する**（v0.3）。直接編集・箱の移動・スライド操作・挿入・印・配置案・サイズ/色など、この拡張が原稿に書いたあとは、ファイルも即座に保存される（設定 `marpScrollSync.saveAfterEdit`。既定 on）。未保存のまま置くと、Claude Code など外で同じ原稿を書き換える道具とぶつかって「ディスクの内容の方が新しい」と保存を断られるので、それを防ぐ。Cmd+Z（Ctrl+Z）はそのまま効く（取り消した結果も保存される）。原稿のタブで直接打った文字は対象外（VS Code の `files.autoSave` で）

### スライド単位の操作（v0.2）
プレビューで選んでいるスライドの右上にボタンが出る。同じ操作はコマンドパレットにもあり、プレビューを開いていなくても、カーソルのあるスライドに対して使える。

| ボタン | 意味 | コマンド |
|---|---|---|
| ＋ | 新しいスライドをこの次に作る（空白／見出し＋箇条書き／split／fig／message／divider から型を選ぶ） | `Marp: 新しいスライドを次に入れる…` |
| ⧉ | このスライドを複製する（完成の印は複製側に付けない） | `Marp: このスライドを複製` |
| ↑ / ↓ | 前へ／後ろへ移す | `Marp: このスライドを前へ` / `…後ろへ` |
| 🗑 | 削除する（確認あり） | `Marp: このスライドを削除…` |
| ★ | 完成スライドの印を付ける／外す | `Marp: このスライドに「完成」の印を付ける／外す（ライブラリ）` |
| 📚 | 既存のスライドを検索して、この次に挿入する（全面ギャラリー） | `Marp: 既存のスライドを検索して挿入…`（＋ポップアップ）／`Marp: ライブラリから完成スライドを挿入…`（★ だけ） |

### 完成スライドのライブラリ（v0.2）
- 出来のよいスライドに **★** を付けておくと、別のデックから呼び出して再利用できる。印を付けるときに id（半角英数とハイフン。リポジトリ内で一意）とタグ（カンマ区切り・省略可）を聞かれる。印付きのスライドは、プレビューと原稿のスライドラベルに ★ が出る
- **📚** でサムネイル一覧がプレビュー内に開く。選ぶと、今のスライドの次に入る。コマンドパレットから挿入した場合は、配色が元デックと違うとき「このデックの色に合わせる／元の色のまま」を選べる
- 挿入のとき、貼り付け先に合わせて次のことを行う
  - ヘッダー・ロゴ・テーマ色：何もしない（貼り付け先の frontmatter に自動で従う）
  - 素材（`./src/…`）：貼り付け先の `src/` へコピー。同名で中身が違うファイルがあれば `-2` を付けて本文の参照も直す
  - デック固有の CSS：そのスライドが使うクラスの定義だけを、貼り付け先 frontmatter の `style:` の末尾へ足す。貼り付け先に同名で中身の違うクラスがあるときは、そのスライドの中の `<style scoped>` に入れる
  - 色：元デックの配色（`--accent` など4値）と完全に一致する色コードを `var(--accent, #元の色)` の形に置き換える（属性値と CSS の中だけ）
  - 貼り付けたコピーには印の代わりに `_from: <id>` が残る
- **テーマが違うデックへ入れると警告が出る**。余白や文字サイズが変わり、本文が縦に伸びて takeaway 帯に重なることがある（自動では直さない）。挿入後は PNG で目視する
- サムネイルは `Marp: ライブラリの台帳とサムネイルを作り直す`（ターミナルで `npm run library` と同じことを実行）で作る。サムネイルが無くても一覧と挿入は使える
- 別のデックからスライドを**ふつうにコピー＆ペースト**したときも、対応している VS Code では「貼り付け先に合わせて貼り付け」を選べる（設定 `marpScrollSync.adaptivePaste`）
- デックをフォルダごと複製すると、同じ id の印が2か所にできる。重複した id は一覧に出ず、挿入もできないので、片方の印を外すか id を変える
- Claude やターミナルからは CLI を使う：`node tools/marp-library.mjs --help`（`index` / `thumbs` / `list` / `candidates` / `mark` / `unmark` / `insert`。`insert … --dry-run` で計画だけ確認できる）

### 既存のスライドを検索して入れる（＋ポップアップ・棚）
リポジトリの `slides/` にある**全デックの全スライド**が対象（★ の有無を問わない。`_library`・`out`・`work`・`old`・`orig`・`parts`・`.bak` は除く）。

- **＋ボタン**：プレビューのスライドとスライドの間（1 枚目の上・最後の下も）にマウスを乗せたときだけ出る。キーボードでは `+` か `i`（現在のスライドの次）。コマンドは `Marp: 既存のスライドを検索して挿入…`
- 押すと、その場に**小さなポップアップ**が開く。上から、検索欄・**棚**（名前つきのサムネイル。3 列・最大 9 枚）・「手を入れた順」の上位。検索欄に打つと結果に置き換わる（空白区切りで AND。題名・本文・タグ・デック名・型・棚の呼び名に当たる）
  - サムネイルを**クリックで即挿入**。**Shift+クリックで複数選択**して「ここに挿入」（選んだ順に入り、何枚でも Cmd+Z 1 回で戻る）
  - 右上の「もっと探す」で**全面ギャラリー**（絞り込み `★ 完成だけ`、並び `関連順／手を入れた順／新しい順`、24 件ずつ「もっと見る」、「原稿を開く」）。📚 ボタンも同じギャラリーを開く
  - Esc・外側クリックで閉じる
- **棚と名前付け**：カードの「名前を付ける…」で、呼び名（例「自己紹介 学外用」）と棚（新しい棚も作れる）を決めて置く。元のデックは書き換えない（★ も要らない）。棚の中はドラッグか Alt+←→ で並べ替え、呼び名はダブルクリックで直す、× で棚から外す。正本は `slides/_library/shelf.json`（git で追跡する。手や CLI で書き換えたら、次に開いたとき読み直す。JSON が壊れているときは、直るまで拡張は書き込まない）。元のスライドが見つからなくなった項目は「行方不明」として残す
- **元の色のまま**：チェックすると、元デックの配色を `var(--accent, …)` に置き換えない
- **元の組版を保つ**：テーマが違うデックから入れるとき、元テーマの本文サイズ・行間・箇条書きの間隔などを、そのスライドの `<style scoped>` に持ち込む（`/* ss-keep-typo:start … */ 〜 /* ss-keep-typo:end */`。この塊を消せば貼り付け先の組版に戻る）。ヘッダ・題・配色は貼り付け先のまま。academic → tsutawaru-academic で収まりやすいことを実測で確かめた。部品テーマ（非同梱） → tsutawaru-academic は改善するが収まり切らないことがある
- **⚠ はみ出し**：本文が下へはみ出す・takeaway 帯やヘッダー帯・隣のブロックに食い込むスライドには、プレビューの枠の上に `⚠ はみ出し` が出る。挿入した直後のスライドがはみ出していたら、「スライド n が ◯px はみ出しています（元の組版を保つ で入れ直すか、右クリックで別の配置を試せます）」と知らせる。**最後は必ず PNG で目視する**（検知は表の中・インライン SVG の中は見ない）
- **索引**：メモリに持つ。`slides/_library/corpus.json`（生成物・git 管理外）が無い・古いときは、履歴の集計（添削回数）抜きの索引をその場で作って応え、裏で `node tools/marp-library.mjs corpus` を 1 本だけ走らせて、終わったら読み直す（その間はギャラリーに「索引を作成中」と出る）。手で作り直すときは `Marp: スライド検索の索引を作り直す` か `npm run corpus`（`npm run library` にも含まれる）。未保存の原稿の内容も検索とサムネイルに映る
- CLI（Claude やターミナルから）：
  ```bash
  node tools/marp-library.mjs search 自己紹介 [--marked] [--sort score|recent] [--theme x] [--top N] [--json] [--no-shelf]
  node tools/marp-library.mjs shelf list
  node tools/marp-library.mjs shelf add <md> <番号> --shelf 自己紹介 --label "自己紹介 学外用"
  node tools/marp-library.mjs shelf move / remove / rename …      # 番号は 1 始まり。詳しくは --help
  node tools/marp-library.mjs insert --from <md> --slide <n> --into <md> --after <n> [--dry-run]
  ```

### 右クリックで配置案を見比べる（tsutawaru-academic）
- 「素の構造」のスライド（見出し・箇条書き・段落・図だけで、レイアウト用の div で包んでいないもの）を**右クリック**すると、同じ Markdown のまま `_class` に 1 語（`lay-*`）足したらどう見えるかを、小さなサムネイルで並べる。先頭は「標準」（`lay-*` を外す）。項目が 3 つなら 3 列カード・上罫の見出し列、4 つなら 2×2、図があれば図と文の 2 カラム、のように内容に合う案だけを出す（1 枚で見比べるのは 3 つまで、の規則に反する案は出さない）
- 案にマウスを乗せると、いまのスライドの枠に一時的に反映する（離すと戻る）。はみ出す案には ⚠ が付く。クリックで `_class` を書き換える（★ の印やほかのクラスは保つ。Cmd+Z 1 回で戻る）
- コマンド `Marp: このスライドの配置を変える…` は、カーソルのあるスライドに合う案を一覧から選ぶ（プレビューを開いていなくても使える）
- 配置クラスの CSS は `theme/tsutawaru-academic.css` の §14。ほかのテーマのデックでは、クラスを足しても見た目は変わらない

### Alt で箱を動かす・大きさを変える
- プレビューで **Alt（mac は Option）を押している間**、ポインタの下の要素に枠線と「タグ名.クラス 幅×高さ」の札が出る。**Alt+クリックで選択**すると 8 つのハンドルつきの枠になる（選んだあとは Alt を離してよい）
- **ドラッグ＝移動、ハンドル＝大きさ**。画像・svg・動画は縦横比を保つ（Shift で解除）。ほかは自由（Shift で比率固定）。**矢印キー＝1px、Shift+矢印＝10px**（連打は 0.4 秒の無操作でまとめて 1 回の編集）。**Alt+↑＝親の箱へ、Alt+↓＝元の子へ**。**`0`（ゼロ）＝位置と大きさを元に戻す**。**Esc・外側クリックで終了**
- スライドの中央線・兄弟要素の端・元の位置に 6px 以内で吸い付き、案内線が出る（Cmd/Ctrl を押している間は吸着しない）
- 原稿に書くのは、その要素の**開始タグの `style` 属性だけ**：位置は `translate: Xpx Ypx`（見た目だけ動き、周りは動かない。0,0 になったら消す）、大きさは `width` / `height`（周りは流し込み直される）。ほかの宣言・順序・末尾の `;` は保つ。デックの CSS が `!important` のときだけ `!important` つきで書く。標準の marp-cli の PDF / PNG でも同じ位置・大きさになる（実測で一致）
- **Markdown の画像 `![](…)` は大きさだけ**（alt に `w:NNNpx h:NNNpx`）。動かしたいときは `<img>` で書く。**Markdown の要素（段落・箇条書き・見出し）は対象外**で、選ぶと理由が 1 行出る（Alt+↑ で、書き戻せる親の div へ上がれる）。SVG の中の図形も対象外
- 大きくして下の内容が押し出されたら、いつもの ⚠（はみ出し）で知らせる。流し込みの takeaway 帯（summary 型）の下へ本文が潜った場合も ⚠ が出る
- 箱を選んでいる間は、クリックでの原稿への移動・ダブルクリックの直接編集・右クリックの配置案は止まる。文字の編集中は箱を選べない

| 送る量 | 同上。1 枚だけ変わったとき | patch 約 15KB（従来の render は毎回 約 1.6MB） |
| 全体の描き直し（render）と patch の比 | 88 枚・3.4MB | render 約 43ms／patch 中央値 1.2〜1.4ms |
| ＋ポップアップの初回表示 | 棚 9 枚＋上位 6 枚・headless Chrome | 骨組み 8〜12ms、サムネイルが全部埋まるまで 18〜23ms |

| 検索への応答（拡張側） | 実リポジトリ 165 デック・約 4,000 枚、9 件 | サムネイル未作成のデックを含むとき 83〜125ms、作成済みなら 8〜13ms |

| ＋ をクリック → 棚と「手を入れた順」のサムネイルが全部埋まる | tsutawaru の新規デック 3 枚・実デック 4 本の索引（約 220 枚） | 初回 34ms、2 回目以降 17〜20ms。80 枚のデック上でも 17ms、索引の裏作成中でも 28〜38ms |

| 索引づくり | 同上 | 履歴抜き・初回 0.4〜0.5 秒（プレビューを開いた直後の空き時間に 1 回）、2 回目以降 約 0.12 秒（応答の後で実行）。履歴つきは CLI で約 6 秒（裏の子プロセス） |

- サムネイルの描画に 90ms 以上かかりそうなとき（初めてのデックが多い検索）は、先に題名だけのカードを返し、描けしだい同じ検索の応答をもう一度送る。
- プレビューの再描画は、**変わったスライドだけ**を送る（枚数・CSS が同じとき）。スクロール位置・ほかのスライドの画像や動画の状態はそのまま。枚数や `style:` が変わったときは全体を送る。
- 原稿を触ると、最後の入力から 1.5 秒後に索引を裏で作り直す（約 0.12 秒。印を付けた直後の 📚 に ★ が映るように）。
- shelf.json を外で書き換えたとき（CLI・手編集・git pull）は、次の検索の応答に棚を載せ直す。プレビューを開き直さなくてよい。
- VS Code 実機の Webview では未計測（上は Node と headless Chrome での値）。

### 原稿の折りたたみとラベル（v0.2）
- Marp の原稿を開くと、**カーソルのあるスライド以外を畳む**。カーソルやプレビューの選択が別のスライドへ移ると、前のスライドを畳み、今のスライドを開く。開いたスライドの中でも `style`・インライン SVG は畳んだまま
- 切り替え：ステータスバーの **「自動たたみ」** をクリック、または `Marp: スライドの自動折りたたみ オン／オフ`。`Marp: 今のスライド以外を畳む` / `Marp: すべてのスライドを開く` もある。検索中・複数カーソル・範囲選択中は畳まない
- 各スライドの区切り行に `  12 ｜ summary ｜ 今回の構成 ★` のような**スライドラベル**、`<div class="left">` などの行末に `◀ 左パネル` のような**区画ラベル**を薄く表示する。どちらも表示だけで、原稿には書かない
- 区画ラベルを原稿に残したいときだけ `Marp: このスライドのパネル名をコメントとして原稿に書く` を使う（→「書き戻される記法」）
- 発表者ノートに混入する位置にある短いコメント（ラベル風のもの・`#region`）と、`_class` の無い単独の `_lib` の印には、エディタに注意（波線）を出す

## 使い方
1. `marp: true` の `.md` を開く
2. ステータスバー右の `Slide n/N` をクリック、または **Cmd+K M**(`Marp: Open Synced Preview`)
3. コマンドパレット `Marp: Go to Slide by number…` で番号ジャンプも可能
4. **文字を直す**：プレビューの文字をダブルクリック → 直す → **Enter**
5. **サイズ/色を変える**：プレビューで文字をドラッグして選ぶ（またはクリックで原稿の該当行へ飛び、エディタで文字を選択）→ ツールバーの `A+/A−`・↑↓・`Cmd+Alt+=/−` で 1px ずつ、`🎨`/`Marp: 選択文字の色を変える…` で色、`✕` で解除

## 書き戻される記法
この拡張が原稿に書くのは次のものだけ。どれも手書き・後編集してよい。

**文字の編集**：直した文字そのもの。Markdown の記号として解釈される文字（`* _ \ ` < [`）を新しく打ったときだけ、バックスラッシュでエスケープして書く。

**サイズ/色（ss-tune）**：テーマ CSS より優先される `!important` 付きの span。
```html
本文の<span class="ss-tune" style="font-size:26px !important; color:#A6192E !important">ここだけ</span>大きく赤く
```

**配置クラス（lay-*）**：右クリックの配置案を選ぶと、そのスライドの `_class` に `lay-cards3` のような 1 語が入る（無ければ `_class` のコメントを足す。グローバル `class:` があればその値も写す）。「標準」を選ぶと外れる。

**元の組版（ss-keep-typo）**：「元の組版を保つ」で入れたスライドの `<style scoped>` の中の、`/* ss-keep-typo:start … */` 〜 `/* ss-keep-typo:end */`。

**棚（slides/_library/shelf.json）**：原稿ではなく、この JSON に呼び名と並び順だけを書く。

**完成スライドの印（_lib）**：`_class` と同じコメントの中に1行で入る。形は `id | タグ(カンマ区切り) | 日付`。
```html
<!--
_class: summary
_lib: alc-agenda | 構成, アジェンダ | 2026-09-20
-->
```
`_class` の無いスライドに印を付けると `_class:` の行も足す（値は、デック全体の `class` 指定があればそれ、無ければ空）。ライブラリから入れたコピーには `_lib` の代わりに `_from: alc-agenda` が入る。
`_class` の行を消して `_lib` だけにすると、その行が**発表者ノートに出る**（Marp は、知っているキーが1つも無いコメントをノートとして扱うため）。エディタに注意が出る。

**箱の位置と大きさ**：開始タグの `style` 属性に `translate` / `width` / `height` だけ（Markdown の画像は alt の `w:` / `h:`）。消せば元に戻る。
```html
<img src="./src/slido-qr.png" alt="…" style="width: 180px; height: 180px; translate: 40px 0px">
```

**区画ラベル**：開始タグと**同じ行**の行末にだけ書く。単独行のコメントは発表者ノートに入るので書かない。
```html
<div class="left"> <!-- ◀ 左パネル -->
```

**ライブラリからの挿入・貼り付け**：スライド本文、frontmatter `style:` 末尾の CSS（`/* ── ライブラリ <id> の部品 … ── */` の見出し付き）、必要なときだけスライド内の `<style scoped>`、色の `var(--accent, #hex)` 置換、`src/` への素材コピー。

確認済み（2026-09-20、実デックの写し3本・marp-cli v4.5.1）：印（5枚）と区画ラベル（書ける区画すべて・計105か所）を書いても PNG は全50ページ画素一致、`--notes` の出力も一致。ライブラリ挿入で足した CSS は既存スライドの PNG を変えず、挿入で増えるノートは挿入したスライド自身のノートだけ。`npm run pdf` も通る。

## 安全の仕組み
- **位置が確定できなければ書かない**。プレビューの文字が原稿のどこにあたるかを一意に特定でき、その位置の文字が編集前の表示と一致したときだけ書き換える。特定できないとき（リンクやコードの中、太字記号の境目、数式、絵文字の `:名前:` など）は原稿を変えず、プレビューに理由を出して原稿の該当行へ案内する
- **1操作＝Cmd+Z 1回**。文字の編集・箇条書きの追加・スライド操作・印・挿入は、どれも1回の取り消しで元に戻る（素材のコピーは残る）
- **書いたらすぐ保存する**。この拡張が原稿に書いた直後にファイルも保存する（`marpScrollSync.saveAfterEdit`）。ディスクと VS Code の原稿が食い違う時間を作らないので、外で同じ原稿を書き換える道具（Claude Code など）と衝突しない。保存に失敗しても書き戻し自体は成功扱い（ログに出すだけ）
- プレビューを描いたあとに原稿が変わっていたら書き戻さない（「原稿が先に変わりました。もう一度お試しください」）
- スライド操作は、操作後の枚数を数え直して想定と違えば何も書かない。`***`・`___`・字下げした `---`・`headingDivider` など、この拡張の数え方が marp と食い違う書き方のある原稿では、スライド操作を断って該当行へ案内する
- 書き戻したあと再描画した文字が入力と違っていれば「表示と原稿がずれました（Cmd+Z で戻せます）」と出す
- 箱の編集は、原稿の開始タグを「スライドの先頭から」と「直前の空行から」の 2 通りで数え、同じタグに行き着き、タグ名も合ったときだけ書く
- 直接編集・ライブラリ・折りたたみ・箱の編集のどれかが読み込めなくても、同期プレビュー本体は動く

## うまく行かないとき
- **ダブルクリックしても編集にならない**：ヘッダー帯・フッター・数式・画像の中の文字は対象外。原稿で直す
- **「原稿の該当行で直してください」と出る**：安全に書ける位置を確定できなかった。原稿は変わっていない。案内された行で直す
- **スライド操作を断られる**：上の「数え方が食い違う書き方」が原稿にある。案内された行の区切りを、前後に空行のある `---` に直す
- **リポジトリの写しで CLI を試す**：`--root <写し>` を付ける（コマンドの前後どちらでもよい）か、写しのフォルダの中で実行する。対象は実行時に 1 行表示される
- **📚 の一覧が空・目当てのスライドが出ない**：印がまだ無いか、同じ id が2か所にある（`node tools/marp-library.mjs index` が重複を知らせる）
- **サムネイルが出ない**：`Marp: ライブラリの台帳とサムネイルを作り直す` を実行する
- **挿入したスライドの見た目が崩れた**：テーマ違い（部品テーマ（非同梱） の部品を academic に入れた等）。警告に出たクラス名を確認し、貼り付け先のテーマの部品に置き換えるか、レイアウトを直す
- **畳まれて編集しづらい**：ステータスバーの「自動たたみ」で切る
- **Cmd+Alt+=/− が効かない**：marp の md を編集中（エディタにフォーカス）のときだけ有効
- **拡張のボタンや表示が出ない**：リポジトリ直下で `npm run setup`（拡張のリンクを貼り直す）→ VS Code を再読み込み

## スライド番号の算出
frontmatter を除外し、コードフェンス内を無視、直前が空行の `---` のみをページ区切りとして数える（正本は `lib/slide-split.cjs`）。
78 枚の実デックで marp-core の実レンダリング枚数と一致を確認済み。

## 開発者向け
- vscode に依存しないロジックは `lib/*.cjs` の純粋関数。拡張に新しい npm 依存は足さない（`@marp-team/marp-core` のみ）
- 日本語 IME・初回の自動折りたたみのタイミング・貼り付け適応は VS Code 実機でしか確かめていない
