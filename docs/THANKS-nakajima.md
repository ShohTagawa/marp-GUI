# 中島聡さんへの感謝と、`marp-GUI` の設計思想について

このドキュメントは、`marp-GUI`（および千葉大学での講義スライド・オンデマンド動画生成環境 `marp-ChibaU`）の設計と実装にあたり、大きな示唆と直接の技術的恩恵をいただいた **中島聡さん（[@snakajima](https://x.com/snakajima) / Receptron）** への感謝と、本ツールの構造的な解説をまとめたものです。

特に、中島さんの記事 **「バイブなもの作りの時代」**（`AvatarScript`・`JingleScript`・`MulmoCast` を巡る一連の実践と洞察）は、本プロジェクトのアーキテクチャを決定づける直接のきっかけとなりました。

---

## 1. 「AIに特定の仕事をさせるための言語（DSL）」としての CSS テーマ＋Markdown

中島さんは記事の中で、Live2D風アバターを動かす `AvatarScript` や音楽・効果音を生成する `JingleScript`、`MulmoScript` について、**「AIに特定の仕事をさせるための言語（DSL）」** と位置づけておられます。LLM に生の波形やピクセル座標を直接吐かせるのではなく、LLM が迷わず書けて、かつ決定論的なエンジンが確実にレンダリングできる「器（フォーマット）」を定義するというアプローチです。

`marp-GUI` は、この発想を **学術・講義スライドの作成** にそのまま適用しています。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 1. CSSテーマ（theme/*.css ＋ 12種の <!-- _class: lay-* -->）          │
│    ＝ AIと人間が共有する「器（DSL）」                                │
│    ・見出し・ヘッダー・要点帯（.takeaway）の座標はCSS側で固定        │
│    ・本文の並び方だけを _class の1語（lay-cards3, lay-flow 等）で指定 │
│    ・器のデザイン自体を変えたいときは、AIにCSSの調整を依頼可能       │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ 流し込む
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 2. 素の Markdown 原稿（slides/<deck>/<deck>.md）                     │
│    ・AIエージェント（Claude Code / Antigravity IDE）が高速に生成     │
│    ・過去の4,000枚以上のスライド資産も、差し込むだけで今のCSSに馴染む │
│    ・各スライド末尾のコメント（<!-- ... -->）がそのまま発表原稿になる │
└───────────────────────────────▲──────────────────────────────────────┘
                                │ 1回の Undo（⌘Z）で逆変換して書き戻す
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 3. 同期プレビュー GUI（VS Code / Antigravity IDE 拡張）              │
│    ・文字のダブルクリック編集、右クリックでの配置案（lay-*）切り替え  │
│    ・Alt＋ドラッグによる枠（div / SVG）の移動・リサイズ              │
└──────────────────────────────────────────────────────────────────────┘
```

LLM に PowerPoint の複雑な XML や自由座標の HTML を毎回ゼロから書かせると、ページごとに余白やフォントサイズ、見出し位置が微妙にズレてしまいます。
そこで `marp-GUI` では、MIT ライセンスの [Marp (Marpit)](https://marp.app/) を土台に、**「CSS の中にスライドの構造（不変条件）を埋め込み、AI には素の Markdown と `_class: lay-*` の 1 語だけを書かせる」** という構造を採りました。

さらに重要な点として、人間が右側のプレビュー画面上で文字をダブルクリックして直したり、右クリックで配置案を選んだり、`Alt`＋ドラッグで枠を動かしたりしたときも、GUI 側が独自のバイナリ状態を持つのではなく、**同じ Markdown 原稿（DSL）への 1 回の編集（`⌘Z` 1 回で戻せる単位）として逆変換して書き戻す** ように作られています。これにより、AI エージェントと人間が同じ 1 つの `.md` ファイルを違和感なく往復できます。

## 2. 「トークンではなく、手元の Mac に重い計算をさせる」役割分担

中島さんは記事の中で、3D 映像を LLM に作らせた経験から次のように指摘されています。

> LLM が書くのは 3D 映像を描画する HTML のコードだけで、一番処理が重いのは、それを手元で 3D レンダリングする部分です。（中略）トークンの使用量は爆発的には増えなかったので、ほとんどの仕事は私のパソコン（MacBook Pro）がしていた計算になります。正確には「AI 処理よりも、通常の計算処理の比重が重くなる」と考えた方が良いと思います。

`marp-GUI` と動画生成パイプライン（`marp-ChibaU`）も、まさにこの役割分担で動いています。

- **AI（LLM）が担う仕事（トークン消費が極めて少ない部分）**
  - スライドの骨格・本文（Markdown）の執筆
  - 12 種類の配置クラス（`lay-*`）の選択と、インライン SVG 図解の記述
  - 必要に応じた `theme/*.css` の余白・配色調整
  - 各スライド末尾の `<!-- ... -->` への発表者ノート（講義の読み上げ原稿・課題・時間配分）の生成
- **手元の Mac / PC（CPU・GPU）が担う仕事（決定論的ハーネス）**
  - エディタのカーソル移動に追従する同期プレビューと、非編集ページの自動折りたたみ
  - `git log` の改訂履歴から過去 4,000 枚超のスライドを「手を入れた順」に索引化するローカル検索（`tools/marp-library.mjs`）
  - Headless Chrome（`puppeteer-core`）を用いた分割レンダリングによる、文字が一切ラスタライズされないベクター PDF 出力（`tools/marp-pdf/`）
  - スライドの発表者ノートからの音声合成（GCP Text-to-Speech）、ローカルの `whisper.cpp` による強制アラインメント、そして **中島さんの `AvatarScript`（`receptron/avatarscript`）＋ `onnxruntime-node` と `ffmpeg` による字幕・アバター付き講義動画のレンダリング**

## 3. `AvatarScript`・`MulmoCast`・`Mesh Avatar Studio` への感謝

この `marp-GUI` の使い方動画、および講義用のオンデマンド動画パイプライン（`tools/marp-video/build-video.mjs`）では、中島さんが公開された **[AvatarScript](https://github.com/receptron/avatarscript)** と **[MulmoCast](https://github.com/receptron/mulmocast-cli)**、そして shinshin86 さんの **[Mesh Avatar Studio](https://x.com/shinshin86/status/2106593371762651346)** を直接組み込んで活用させていただいています。

中島さんが記事で書かれていた通り、動画生成 AI のリップシンクはコストも時間もかかり、何より Markdown や HTML で作ったプレゼン資料と綺麗に重ねて大量生産することが困難でした。
`AvatarScript` がオープンソースとして公開されたおかげで、**「Marp のスライド（Markdown＋CSS）＋ 発表者ノート（読み上げ原稿）」から、右下に自分のアバターが立ってしゃべる講義動画をコマンド 1 つで自動合成する** という、大学教員にとって夢のようなワークフローが実現しました。

## 4. 「バイブなもの作り」と、人間に残された「何を動かさないか」の定義

> ソフトウェアの開発コストが限りなくゼロに近づいた今、ビジネスモデルとかは考えずに、自分が作りたいと感じたものをまずは作ってみる、そんな「バイブなもの作り」の時代が来ているのです。そんな時代に人間に残された仕事は何かというと、「何を作るか」「何が良いか」「何が正しいか」を判断すること、つまり「センス」と「判断力」と「倫理観」です。
> — 中島聡「バイブなもの作りの時代」

`marp-GUI` のコードベース（VS Code / Antigravity IDE 拡張、PDF 出力ハーネス、5 つの CSS テーマ、および 346 件の自動テスト）の大部分は、AI コーディングエージェントとの「バイブコーディング」によって書かれました。

その中で人間である作者が定義したのは、機能一覧ではなく **「どんな体験をするか」** と **「何を動かさないか（不変条件）」** でした。

1. **ヘッダーとタイトルの位置を動かさない**（ページをめくったときに視線が飛ばない）
2. **下端の要点帯（`.takeaway`）を動かさない**（1 枚 1 メッセージの着地点を固定する）
3. **16:9 の外枠とベクター文字を崩さない**（どの環境でも同じ PDF・発表画面になる）
4. **人間の直接操作を 1 回の `⌘Z`（Undo）で必ず元に戻せるようにする**

中島さんの記事とオープンソースの成果物に背中を押され、「自分が毎日の講義や研究発表で本当に欲しいもの」をバイブスそのままに形にすることができました。心より感謝申し上げます。
